# Рассылки в GetCourse

Скилл для создания email-рассылок в GetCourse: переменные, правила вёрстки, проверка кроссплатформенности, импорт готового HTML. Основа — заметка `getcourse-mailings.md`.

---

## Подключение MCP

**Для загрузки файлов сразу в файловое хранилище GetCourse необходимо подключить MCP-сервер GetCourse с доступным инструментом загрузки файлов (`upload_file`).** Перед загрузкой проверь наличие этого инструмента в текущей сессии и используй его согласно доступной схеме параметров. Ссылку на файл бери из ответа инструмента.

Если MCP не подключён или инструмент загрузки недоступен, предложи подключить MCP через настройки используемой среды. При этом можно сразу создать письмо с плейсхолдерами на месте картинок; затем пользователь отдельно загружает картинки вручную на платформе и заменяет плейсхолдеры полученными ссылками (см. раздел «Картинки и загрузка файлов»).

Для остальных операций с GetCourse используй доступные MCP-инструменты, которые их поддерживают.

**Свои переменные из дополнительных полей.** При подключённом MCP получай список доп. полей аккаунта инструментом `get_account_fields` (возвращает поля контекстов `user` и `deal` с типами). Эти поля доступны в письмах как переменные: в рассылке по пользователям — `{Заголовок поля}`, в рассылках по заказам и покупкам — `{user.Заголовок поля}`. Перед использованием поля в письме сверяй его точное название (пробелы, регистр) со списком.

### Подключение к ZCode

Endpoint — `https://<школа>.getcourse.ru/pl/mcp`, где `<школа>` — имя аккаунта (системный поддомен GetCourse; кастомный домен школы не подходит). Авторизация OAuth через браузер под администратором школы.

Конфиг `~/.zcode/cli/config.json`:

```json
{
  "mcp": {
    "servers": {
      "getcourse": {
        "type": "http",
        "url": "https://<школа>.getcourse.ru/pl/mcp",
        "oauth": {
          "type": "authorization_code",
          "redirectPath": "/callback"
        }
      }
    }
  }
}
```

**`oauth.redirectPath: "/callback"` обязателен.** Без него ZCode шлёт redirect_uri с путём `/oauth/callback/mcp/<имя-сервера>`, который сервер авторизации GetCourse отвергает ошибкой `{"error":"invalid_request"}` на шаге выдачи доступа (уже после логина). Облачные клиенты (ChatGPT, Claude) с этим не сталкиваются — у них редирект на их собственный https-домен, поэтому проблема выглядит как «у всех работает, а в ZCode нет».

Подключение: полностью перезапустить ZCode → **Settings → MCP** → подключить `getcourse` → в открывшемся браузере войти админом школы и нажать **«Разрешить доступ»**.

Если авторизация раньше застревала с ошибкой — из `~/.zcode/v2/credentials.json` удалить ключи вида `mcp:oauth:<hash>:*` (кэш OAuth) и повторить подключение после перезапуска.

## Рабочий процесс

1. Собери письмо как **один HTML-файл**: табличная вёрстка, все стили инлайн в `style`-атрибутах, без внешних CSS-файлов.
2. Открой файл в браузере и оцени результат: сетка, шрифты, цвета, узкий экран.
3. Недочёты исправляй итерациями: покажи конкретную проблему, попроси исправить, снова проверь.
4. Проверь каждое использованное CSS-свойство на [caniemail.com](https://www.caniemail.com/). Письмо без этой проверки не считается готовым.
5. Подготовь картинки по разделу «Картинки и загрузка файлов»: загрузи через MCP или оставь плейсхолдеры для ручной загрузки. Перед тестовой отправкой замени все плейсхолдеры реальными ссылками.
6. Вставь HTML в GetCourse скриптом импорта (см. ниже), сохрани и отправь **тестовое письмо** себе. Подстановка переменных в тесте ограничена — финальную проверку делай по реальной отправке.

## Жёсткие ограничения писем

Почтовые клиенты вырезают или игнорируют сложные элементы. В письме **нельзя**:

- **JavaScript** — вырезается всегда;
- **Встроенное видео** — вместо него ссылка или GIF-превью;
- **Сложные анимации** — не поддерживаются большинством клиентов;
- **Внешние стили** — только инлайн `style`-атрибуты и табличная вёрстка.

Если сомневаешься в элементе или свойстве — проверяй на caniemail и тестовой отправкой в нужные клиенты.

## Импорт готового HTML-письма

Скрипт `mailing-import.js` добавляет в редакторе рассылки (`/notifications/control/mailings/update/id/NNN`) плавающую панель «Импорт HTML-письма». Подключение — один раз, вставкой в консоль браузера или через расширение/Tampermonkey:

```html
<script async src="https://school.one-way.dev/chtm/libraries/mailing-import.js"></script>
```

Работа с панелью: выбрать `.html`-файл или вставить HTML в поле → «Импортировать в редактор»:

- `<head>` (без `<title>`) → поле **HEAD письма** (`Mailing[headHtml]`);
- `<body>` → контент письма (`Mailing[content]`, вставка через Summernote);
- `<title>` → тема письма (`Mailing[subject]`, с подтверждением, если тема уже заполнена).

После импорта — «Просмотр кода» / тестовая отправка и «Сохранить».

## Создание рассылки в интерфейсе GetCourse

1. **Рассылки → Создать рассылку.**
2. Выбрать **объект** рассылки (транспорт) — от него зависит набор доступных переменных:
   - **Пользователи** — по сегментам пользователей;
   - **Заказы** — по заказам (письма «осталось оплатить», «заказ создан»);
   - **Покупки** — по покупкам (доступ, даты начала/окончания).

   Если в задаче объект не указан — **уточни его у пользователя до вёрстки**. В письмо прописывай **только** переменные выбранного объекта: заказы и покупки наследуют все переменные пользователей, но переменные заказа/покупки в рассылке по пользователям работать не будут.
3. Задать **условия/сегмент**.
4. Собрать письмо в блочном редакторе или в HTML. Переменные вставляются кнопкой **«Переменные»** — список зависит от объекта.
5. Отправить **тестовое письмо** себе — обязательно.
6. Запустить сразу или по расписанию. Статистика (доставлено/открыто/клики/отписки) — в списке рассылок.

Переменные работают и в процессах (автоворонки): блоки «Отправить email»/«Отправить SMS», триггеры по заказам и покупкам. Часть переменных доступна **только в процессах** — это отмечено в таблицах.

## Общие правила переменных

- Переменные привязаны к объекту рассылки: **пользователи → заказы → покупки** (каждый следующий включает переменные предыдущего). Транспорт письма уточняй до вёрстки и предлагай/прописывай только соответствующие ему переменные.
- Синтаксис: `{имя_переменной}`. Если данных нет — подставляется пустота.
- Дополнительные поля аккаунта — тоже переменные: в рассылке по пользователям — `{Заголовок поля}`, в рассылках по заказам и покупкам — `{user.Заголовок поля}`, поля заказа — по заголовку. Список своих полей не выдумывай: при подключённом MCP возьми его инструментом `get_account_fields` (см. «Подключение MCP»); название поля вставляй как есть, включая пробелы и регистр.
- Значение из GET-параметра страницы: `{query.prmName|defaultValue}`.
- Даты по умолчанию в формате `d.m.Y` — форматирование: [getcourse.ru/blog/524711](https://getcourse.ru/blog/524711).

## Картинки и загрузка файлов

### Если MCP подключён и загрузка доступна

1. Загрузи подготовленные файлы через MCP-инструмент `upload_file` по его текущей схеме параметров.
2. Используй возвращённые ссылки в HTML-письме. Не придумывай URL файлов.
3. Проверь отображение картинок в тестовом письме.

### Если MCP не подключён или загрузка недоступна

1. Создай HTML-письмо с понятными плейсхолдерами на месте картинок, например `{{IMAGE_1_URL}}` в атрибуте `src`, и содержательными `alt`-описаниями. Это временные метки для замены, а не переменные GetCourse.
2. Передай картинки отдельно и список соответствий: плейсхолдер → имя файла → место в письме.
3. Пользователь загружает картинки вручную в файловое хранилище через интерфейс GetCourse и заменяет каждый плейсхолдер ссылкой загруженного файла.
4. До отправки рассылки убедись, что все плейсхолдеры заменены, и проверь картинки в тестовом письме. До замены это черновик.

**Прямая загрузка файлов выполняется только через подключённый MCP.** Не используй обходные HTTP-запросы для загрузки вместо MCP.
